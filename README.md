# 周转物资、闲置资产平台

财务资产处申报项目 · 中期成果可运行版本

## 快速启动

**推荐：双击 `start.bat`**（Windows）

启动器会最小化运行服务，**关闭启动窗口不会中断服务**，适合长时间挂着演示。
停止服务请双击 `stop.bat`。

**命令行方式**

```bash
node server/index.js
# 打开 http://localhost:3000
```

> 注意：用命令行启动时，若在终端窗口按 Ctrl+C 或关闭该窗口，服务就会停止，
> 浏览器会显示"无法访问此页面"。此时重新启动即可。

零外部依赖，使用 Node 内置 `node:sqlite`（需 Node 22+）。

### 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 浏览器显示"无法访问此页面" / ERR_CONNECTION_REFUSED | 服务进程没在运行 | 双击 `start.bat` 重新启动 |
| 502 | 同上，端口无监听 | 同上 |
| 端口 3000 已被占用 | 上一次服务没退干净 | 双击 `stop.bat` 后再启动 |

启动后可用下面命令确认是否正常：

```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000
# 输出 200 即正常
```

## 真实数据导入

平台已导入学校两份真实周转物资台账（`scripts/extract_sources.py` 抽取 → `scripts/import-real.js` 写库）：

| 源文件 | 内容 | 入库 |
|---|---|---|
| 周转物资-车队三楼库存清单.xls | 车队三楼床上用品 7 条，5060 件 | `materials` + `inventory` |
| 李师傅周转物资明细.xlsx | 田径场/活动中心物资 11 条，3210 件 | `materials` + `inventory` |

导入命令：

```bash
python scripts/extract_sources.py      # 两个周转物资 Excel → import_payload.json
node scripts/import-real.js --dry      # 预览
node scripts/import-real.js --replace  # 清空后重新导入
```

三条关键规则：

1. **同名不同规格视为不同物资条目**。长条桌有 160\*40、120\*50、120\*40 三种，存放地点与数量都不同
   （50 / 261 / 185张），若合并成一条会让库存失真。
2. **模糊数量单独记录**。"马扎 990+" 存为 `total_qty=990` + `qty_note="约990+"`，
   核定发放前提示老师实数核对。
3. **只管周转物资，固定资产不入库**。「资产信息查询.xlsx」里的电脑、打印机等已分配到
   具体部门/使用人，属于资产帐而非物资申领范畴，本平台不导入、不建表。

数据对账：18 种物资，库存合计 8270件，账实全部一致（`available + reserved == total_qty`）。

## 物资归属负责老师（重要）

每种物资绑定**一位负责老师**（`materials.owner_id`）。学生的申领单提交后，
只会出现在该物资负责老师的页面里；其他仓库老师**看不到单据，也无权核定、发放、归还**。

越权调用会被后端拦截并给出明确提示：

```
刘师傅(wh005) 尝试核定长条桌120*50 → {"error":"该物资由「田径场组王师傅」负责，无权操作此单"}
```

资产管理员拥有全局视图，可在「物资负责人绑定」页调整归属，调整后立即生效。
这对应现实中"每种物资由不同老师分管"的场景，也避免了所有仓库老师互相看到对方单据。

## 单据详情页

所有「查看详情」都是**独立页面**，不是弹窗：

- 顶部「← 返回列表」，返回时自动回到进入详情前所在的页签（学生端/管理员端各自记忆）。
- **数量链路**：申请 → 核定 → 实发 → 申报归还 → 实还，五段并排，未发生的环节显示 `-`。
- **缺失数量**高亮，标注「已转学校物资丢失流程，不计入库存」。
- **物资与流程信息**：类别、存放地点、负责老师及电话、使用时间、用途、抵押备注。
- **归还凭证照片**区，无照片时不渲染空区块。
- **流转记录时间线**：谁在什么时间做了什么，含状态迁移。
- **库存流水表**：发放/归还的变动前、变动后数量与说明。

## 业务主流程

```
学生登录 OA → 填写申领 → 导师审批 → 仓库老师核库存
  ├─ 完全通过 → 携学生证线下抵押 → 清点发放 → 按实发扣库存
  └─ 部分通过 → 按核定数改单 → 回到导师审批 → 同上

借用中(in_use)
  ├─ 学生拍照提交归还申请 → return_submitted 待老师清点
  │    · 此时不动库存，因为实还数量尚未确认
  │    · 单据自动路由到该物资负责老师的「待清点归还」
  └─ 负责老师现场清点，填入实际归还件数 → 按实还回增库存
       ├─ 账实相符 → returned已归还
       └─ 账实不符 → 差额标记 missing_qty，转学校丢失流程（不计入库存）
                     → mismatch → 资产管理员核销 → closed
```

## 归还流程（两步）

归还不是一步完成的，而是「学生申报 → 老师清点」两步，因为**实还数量只有老师现场点得出来**。

| 步骤 | 角色 | 动作 | 库存影响 |
|---|---|---|---|
| 1 | 借用人 | 在「我的借用与归还」点**提交归还**，如实填申报数量并**上传照片** | **不动** |
| 2 | 该物资负责老师 | 在「待清点归还」看到单据与照片，填入**实还数量**并清点登记 | 此时按实还回增 |

设计要点：

- **申报量 ≠ 实还量是常态**。学生申报还 60，老师实点 58，系统一律以老师清点结果为准，
  流转记录会留痕「学生申报 60，实际清点 58」。
- **申报归还数超过实发数被拒绝**；实还数超过实发数同样被拒绝。
- **必须至少有照片**。学生提交时必传；老师直接登记时可补拍。
- **待清点单据只对该物资负责老师可见**，其他仓库老师既看不到也无权清点。
- **学生不能替别人归还**，也不能重复提交。
- **老师可直接清点**（学生未线上提交的场景，如现场归还来不及拍照），
  此时库存同样按实还回增。
- 学生提交申请时**不动库存**——实还数量未确认前就回增会虚增库存。

## 核心数据原则

`requests` 表存四个数量，**库存只认后两个**：

| 字段 | 含义 | 是否影响库存 |
|---|---|---|
| `apply_qty` | 申请数量 | 否 |
| `approved_qty` | 仓库核定数量 | 否（触发预占） |
| `issued_qty` | 实际发放数量 | **是，扣减** |
| `return_declared_qty` | 学生申报归还数量 | 否（仅申报，等老师清点） |
| `returned_qty` | 实际归还数量（以老师清点为准） | **是，回增** |
| `missing_qty` | 缺失待处理数量 | **否，仅标记** |

> 借出 60、还回 55 → 库存回到 55，缺失 5 挂在单据上等丢失流程处理。
> 系统宁可让账面显示缺口，也不自动补平，因为实物确实只有 55。

## 库存防超卖设计

`server/inventory.js` 是**唯一**能写 `inventory` 表的模块，遵守六条铁律：

1. 任何路径不得直接 UPDATE inventory
2. 扣减按实发、回增按实还，绝不按申请数
3. 所有增减走原子条件 SQL（`WHERE available + ? >= 0`），不先读后判
4. 账实差额只标记，绝不写库存
5. 每次变动必写 `stock_logs`，只追加不修改
6. 核定环节 `reserve()` 预占，判定口径 `available - reserved`

第 6 条是并发场景的关键。压测结果：

```
60 人并发申领 200 把折叠椅（每人 10 把，负责人赵老师）
→ 核定成功 20 单，库存不足被拒 40 单
→ 库存 200 → 0，reserved 归零无泄漏，无超卖
```

## 接入学校 OA

两个适配器已按接口隔离设计，OA 到位后**只换实现类，业务代码零改动**。

切换方式：

```bash
# 1. 填入 OA 配置
export AUTH_MODE=oa
export APPROVAL_MODE=oa
export OA_APP_KEY=xxx
export OA_APP_SECRET=xxx
export OA_TOKEN_URL=xxx
export OA_USERINFO_URL=xxx
export OA_WORKFLOW_CREATE_URL=xxx

# 2. 按 OA 文档实现 auth-adapter.js 的 verifyFromTicket()
#    与 approval-adapter.js 的 pushTodo()/onResult()

# 3. 重启服务
node server/index.js
```

详见 [OA接入说明.md](./OA接入说明.md)。
